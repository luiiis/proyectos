# Módulo 10: Entrevistas de Trabajo en Inglés

## Las preguntas que SIEMPRE hacen + cómo responder

---

## 1. "Tell me about yourself" (Háblame de ti)

### Estructura de respuesta (60-90 segundos):
```
1. Presente: qué haces ahora
2. Pasado: experiencia relevante
3. Futuro: por qué esta oportunidad
```

### Ejemplo:
```
"Hi, I'm [nombre]. I'm a Full Stack Developer with [X] years of experience.

Currently, I work at [empresa] where I build applications using 
Java Spring Boot for the backend and Angular for the frontend.
I'm responsible for designing REST APIs, managing PostgreSQL databases,
and deploying with Docker and Kubernetes.

Before that, I worked at [empresa anterior] where I learned about
microservices architecture and CI/CD pipelines.

I'm excited about this opportunity because I want to work on 
larger scale systems and continue growing as an engineer."
```

**Pronunciación clave:**
- developer = "divéloper"
- experience = "ikspíriens"
- responsible = "rispónsibel"
- architecture = "árkitekcher"
- opportunity = "oportuníti"
- engineer = "enyiníer"

---

## 2. "What are your strengths?" (¿Cuáles son tus fortalezas?)

### Respuestas para desarrolladores:
```
"My main strength is problem-solving. When I face a bug or a 
complex requirement, I break it down into smaller pieces and 
tackle them one by one. I also document my solutions so the 
team can learn from them."

"I'm a fast learner. I taught myself Spring Boot and Angular 
in 3 months by building real projects. When we needed Kafka 
at work, I was the one who researched it and implemented it."

"I communicate well with non-technical people. I can explain 
complex systems in simple terms, which helps a lot when working 
with product managers and stakeholders."
```

---

## 3. "What's your biggest weakness?" (¿Tu mayor debilidad?)

### Respuestas honestas pero profesionales:
```
"I sometimes spend too much time trying to make code perfect 
before asking for help. I've learned to set time limits — if 
I'm stuck for more than 30 minutes, I ask a teammate."

"I used to struggle with estimations — I would underestimate 
how long tasks take. Now I add a 30% buffer and break tasks 
into smaller pieces to estimate more accurately."
```

## 4. Preguntas Técnicas Comunes

### "Explain [technology] in simple terms"

**REST API:**
```
"A REST API is like a waiter at a restaurant. The client 
(frontend) tells the waiter what it wants, the waiter goes 
to the kitchen (backend/database), and brings back the food 
(data). Each order has a specific format: GET to see the menu, 
POST to place an order, PUT to change an order, DELETE to cancel."
```

**Microservices:**
```
"Instead of one big application that does everything, you 
split it into small independent services. Each one has its 
own database and can be deployed separately. If one fails, 
the others keep running."
```

**Docker:**
```
"Docker is like a shipping container for software. You package 
your application with everything it needs to run — libraries, 
configuration, even the operating system. Then it runs the 
same way on any machine."
```

## 6. Preguntas que TÚ debes hacer al final

```
"What does a typical day look like for this role?"
(¿Cómo es un día típico en este puesto?)

"What tech stack does the team use?"
(¿Qué tecnologías usa el equipo?)

"How does the team handle code reviews?"
(¿Cómo manejan las revisiones de código?)

"What are the biggest challenges the team is facing?"
(¿Cuáles son los mayores retos del equipo?)

"Is there opportunity for learning and growth?"
(¿Hay oportunidad de aprendizaje y crecimiento?)
```

## 7. Ejercicio: Practica en voz alta (graba y escucha)

### Día 1: Preséntate (30 segundos)
### Día 2: Describe tu proyecto actual (1 minuto)
### Día 3: Explica un bug que resolviste (2 minutos)
### Día 4: Responde "Tell me about yourself" completo
### Día 5: Simula toda la entrevista (preguntas arriba)

**Tip:** Grábate con el teléfono, escucha, identifica errores de pronunciación, repite.
